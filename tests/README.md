# 测试与工具

按「是否需要界面、是否联网、是否改本机状态」分成三类，每个脚本都能独立运行。

## 目录

| 目录                  | 内容                              | 特征                           |
| ------------------- | ------------------------------- | ---------------------------- |
| `tests/unit/`       | 纯逻辑单元测试：安装包校验器对抗用例、Ed25519 官方向量 | 无 GUI、无网络、秒级                 |
| `tests/regression/` | 一个脚本对应一个已修复的报障（`_test_*`）       | 多数 headless（offscreen），少数需联网 |
| `tests/ui/`         | 导航 / 圆角 / DPR / 布局的截图与探测        | 需真实桌面会话                      |
| `tools/migrate/`    | 一次性数据迁移（历史安装结构修正）               | 会改本机目录，跑前先备份                 |
| `tools/diagnose/`   | 崩溃复现、二分定位、环境诊断                  | 排障时才用                        |

## 运行

所有脚本内部都用 `Path(__file__).resolve().parents[2]` 定位项目根，  
**不依赖当前工作目录**，在任何地方执行都可以：

```bash
python tests/unit/test_addon_verifier.py
python tests/regression/_test_lts_flag.py
```

没有显示环境时多数脚本会自行切到 offscreen；显式指定更稳：

```bash
set QT_QPA_PLATFORM=offscreen
```

## 产物

测试用 `_settings/` 下的 ini 暂存 `QSettings`，避免污染真实注册表；每次运行前会重建。  
该目录已列入 `.gitignore`。

## 修复记录

**2026-10-19 `core/services/ed25519_pure.py` 修复三处问题，RFC 8032 §7.1 四条向量全部通过（4/4）：**

1. **`_compress()` 缺 Z 归一化** —— 扩展坐标是齐次表示，编码前必须 `x=X/Z, y=Y/Z`。  
   原实现直接取 X、Y，只有 Z=1 的点（如基点本身）碰巧正确；  
   而标量乘的结果几乎都是 Z≠1，导致公钥和签名整体错误。
2. **基点 `G` 的 T 分量写错** —— 误抄成 Y 的值，正确应为 `X·Y mod p`。  
   由于压缩编码只看 x/y，`compress(G)` 依然能对上，掩盖了这个问题；  
   但点加公式里 `C = 2·T1·T2·d` 直接用到 T，一旦做点乘就从 2G 起全部偏离。
3. **测试向量自身被截断** —— RFC 里这条的编号是 **TEST 1024**（不是 TEST 4），  
   其消息长度 **1023 字节**，原测试只抄了前 192 字节。已按 RFC 原文补全。

修复后实测：签名 2.0 ms / 验证 2.1 ms，篡改签名与篡改消息均被拒。

### 影响面（如实说明）

修复前后**运行时行为没有变化**，因为 `core/services/ed25519_pure.py` 目前  
**没有被任何生产代码引用**（全项目只有本测试 import 它）。

`core/services/signature_service.py` 的模块注释写着「v1.5: Ed25519 签名 + 信任根分片」，  
但它实际只做三件事：manifest.json 存在性、必需字段、可选的 SHA-256 checksums 比对，  
**并没有调用 Ed25519**。所以这次的修复是「把预留能力修对」，而不是修一个线上故障。

另外也说明：Ed25519 这条路要走通，`signature_service` 还得补上真正的验签逻辑  
（公钥来源 / 信任根 / manifest 签名段），否则注释与实现仍然不符。
